# 数据集与标注规范 · 智慧养老安全用药辅助平台

> 本文档说明平台三类知识数据（药品知识库 / 冲突规则库 / 科普文章库）与一类视觉数据（药盒检测）的
> 字段规范、来源标注、审核流程与标注方法，供数据维护与后续扩充使用。
> 数据文件位置：`data\medications.json`、`data\rules.json`、`data\science_articles.json`

## 0. 诚实声明（重要）

本项目为课程/大创演示系统，种子数据由开发过程整理自公开的药品说明书要点与权威标准条目
（NMPA 批准说明书文本摘要、AGS Beers 标准 2023、中国老年人潜在不适当用药判断标准 2017 版、各病种中国指南），
**未逐条经过执业药师人工复核**——因此：
- 每条药品带 `source` 字段注明知识来源；
- 每条规则带 `basisSource`（文献依据）与 `reviewedBy`（当前值为"整理自…，待执业药师复核"）；
- 管理后台内置**药师审核工作流**（PENDING → APPROVED/REJECTED），生产上线前必须逐条走完。
数据仅用于演示与教学，**不能作为真实用药决策依据**。

## 1. 药品知识库 medications.json（68 条）

### 字段规范
| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| id | int | 自动 | 入库自增，JSON 中可省略 |
| genericName | string | ✔ | 通用名（含剂型），如"阿司匹林肠溶片"——**识别归一化的主键** |
| brandName | string | | 商品名，如"拜阿司匹灵"，识别与检索都参与匹配 |
| ingredients | string | ✔ | 成分，**逗号分隔 CSV**，冲突引擎按成分做重复/叠加判定，如"对乙酰氨基酚,咖啡因" |
| drugClass | string | 建议 | 药理分类，**CLASS_STACKING 规则按分类命中**，如"非甾体抗炎药(NSAIDs)" |
| indications | string | | 适应证（说明书要点摘要） |
| dosage | string | ✔ | 用法用量（含老年剂量调整提示；RAG"怎么吃"类问题的主要来源） |
| contraindications | string | ✔ | 禁忌（RAG 禁忌类问题来源） |
| precautions | string | 建议 | 注意事项（含药物相互作用要点） |
| adverseReactions | string | | 不良反应 |
| storage | string | | 贮藏 |
| source | string | ✔ | 知识来源标注，统一格式："药品说明书（NMPA批准文本摘要）"或具体指南名 |

### 大白话要求
面向老人的字段（dosage/precautions/contraindications）用**老人能懂的短句**，专业名词后跟解释，
如"肠溶片应在饭前用适量水整片送服，不可嚼碎或压碎，以保证肠溶衣完整、减少胃刺激"。

### 维护途径
- 管理后台「药品知识库」增改（**版本自动+1、留痕、即时同步 AI 词典与 RAG 索引**）；
- 批量导入：按上述字段编辑 JSON 后放入 `data\`，重启后端自动 upsert（以 genericName 判重）。

### RAG 切片规则（自动）
每条药品切 7 个知识片段：`【药名·成分与分类/适应证/用法用量/禁忌/注意事项/不良反应/储存】内容`，
每片段带元数据（title/section/source/med_id）用于**回答逐条标注来源**。当前 68 药 × 7 段 + 科普切片 ≈ 490 片段。

## 2. 冲突规则库 rules.json（39 条）

### 四类规则（ruleType）
| 类型 | 含义 | 判定方式 | 示例 |
|---|---|---|---|
| DUPLICATE_INGREDIENT | 成分重复（同一成分吃两遍） | drugA/drugB 为**成分名**，两药成分集合有交集即触发 | 复方氨酚烷胺 × 对乙酰氨基酚片 |
| CLASS_STACKING | 同类叠加 | drugA 为**药理类别词**（与 drugClass 匹配），≥2 个在用药同类即触发 | NSAIDs 类叠加 |
| CONTRAINDICATED | 禁忌配伍 | drugA/drugB 为药名/成分名，同时在用即触发 | 华法林 × 阿司匹林 |
| ELDERLY_CAUTION | 老年慎用（单药） | drugA 命中即触发，drugB 留空 | Beers：长期 NSAIDs、速释硝苯地平 |

### 字段规范
| 字段 | 必填 | 说明 |
|---|---|---|
| ruleCode | ✔ | 唯一编码，约定 `CR-` 前缀 + 语义缩写，如 CR-ASP-IBU / CR-PIM-NSAID-CHRONIC |
| ruleType | ✔ | 上表四类之一 |
| drugA / drugB | ✔/－ | 匹配词（药名/成分/类别词，引擎做 ~90 条别名归一化 + 双向包含匹配）；单药规则 drugB 为空 |
| riskLevel | ✔ | HIGH / MEDIUM / LOW（展示按 HIGH>MEDIUM>LOW 排序） |
| explanation | ✔ | **大白话解释**：风险机制 + 具体建议，老人能直接听懂 |
| basisSource | ✔ | 依据来源：说明书条目 / Beers 2023 / 中国老年PIM标准2017 / 指南名 |
| reviewedBy | ✔ | 整理人与复核状态，未经复核统一写"…待执业药师复核" |
| reviewStatus | 自动 | PENDING/APPROVED/REJECTED，**只有 APPROVED+enabled 参与校验**（后台审核流控制） |
| version | 自动 | 每次编辑+1，AI 服务热更新时携带 |

### 匹配安全注意
- 匹配词避免过短（≥2字），防止"地平"误伤无关药名；
- 同名不同剂型（硝苯地平片(速释) vs 控释片）必须写**全名**，引擎已限制方向性包含匹配防误报；
- 新增规则先在后台以 PENDING 状态创建 → 用测试账号建计划验证触发 → 药师审核通过上线。

## 3. 科普文章库 science_articles.json（12 篇）

字段：`title`（标题）、`content`（正文，**\n 分段**，每段建议 ≤300 字，RAG 按段切片）、`source`（来源标注）。
主题覆盖：漏服处理、血压测量、多重用药、保健品误区、季节用药、就医带药清单等老年高频场景。
写作要求：短句、大白话、可执行（"怎么做"优于"是什么"）、不出现具体处方建议。

## 4. 药盒检测数据集标注规范（YOLOv8，生产化用）

当前演示用 yolov8n(COCO) 通用检测 + 全图 OCR，并在响应 `detect.mode` 中**如实标注**。
自训药盒检测模型按以下规范执行：

### 4.1 类别定义（单类别起步）
```yaml
# data/medbox.yaml
path: D:/datasets/medbox
train: images/train
val: images/val
names:
  0: med_box     # 药盒（含盒装/瓶装/袋装药品包装）
```

### 4.2 采集要求
- 场景：桌面/手持/床头柜，含倾斜（±30°）、遮挡（≤20%）、弱光、老花镜反光等老年真实拍摄条件；
- 分辨率：手机原图即可（训练时缩放到 640）；每类 ≥1500 张（train:val = 8:2）；
- **隐私**：不得出现人脸、病历号、个人姓名；拍摄真实药盒时遮挡个人信息栏。

### 4.3 标注（LabelImg / X-AnyLabeling，YOLO txt 格式）
- 框住药盒**最小外接矩形**，贴合边缘误差 ≤3px；
- 药名文字区域必须包含在框内（下游 OCR 依赖裁剪区域）；
- 多盒同图逐盒标注；模糊不可辨认的图整图剔除；
- 每张图对应同名 .txt：`class_id cx cy w h`（归一化坐标）。

### 4.4 训练与挂载
```bat
yolo detect train data=medbox.yaml model=yolov8n.pt epochs=100 imgsz=640
set MEDBOX_YOLO_MODEL=D:\models\medbox_best.pt   & rem 启动AI服务即自动启用真实检测裁剪
```
验收指标（申报书口径）：mAP@0.5 ≥ 0.85；识别链路端到端 Top-1 命中率 ≥ 90%（以 `mg_recognize_log` 的
Top-1 与用户 confirm 结果比对自动统计，管理后台可见）。

## 5. 数据质量闭环

- 识别日志记录 Top-3 候选与**用户最终确认**（`chosenMedicationId`）→ 管理后台统计 Top-1 命中率，badcase 回填词典别名；
- 问答日志记录问题/回答/引用/置信度/拒答 → 低分未拒答的问题人工抽查，补充语料或调整阈值（`MEDGUARD_REFUSE_SCORE`）；
- 规则误报/漏报由家属与老人反馈入口收集 → 药师在后台修订规则（版本+1，热推送生效）。
