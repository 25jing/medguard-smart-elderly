> 适用版本 v1.0 · 2026-11 · 单机 Windows 演示环境
> 目标读者：答辩演示者 / 后续接手的开发者

## 2. 一键启动（推荐）

```bat
D:\智慧养老安全用药辅助平台\scripts\start-all.bat
```

脚本依次拉起 MySQL → AI 服务（新窗口）→ 后端（新窗口），等待 8080 就绪后自动打开 H5 与管理后台两个页面。停止用 `scripts\stop-all.bat`。

也可以分窗口手动启动（便于看日志）：`start-mysql.bat` → `start-ai.bat` → `start-backend.bat`。

**启动耗时预期**：MySQL 秒级；后端约 15–30 秒（首次启动会自动建表 + 导入种子数据：68 药品 / 39 规则 / 12 科普 / 演示账号）；AI 服务首次约 2–5 分钟（下载向量模型，走 hf-mirror.com 镜像），之后约 30 秒（FAISS 索引已持久化在 `models\faiss_store\`）。

## 3. 从零部署（新机器）

### 3.1 环境要求
- Windows 10/11 x64（macOS/Linux 同理，脚本需自行改写）
- Java 17+（`java -version` 验证）
- Maven 3.8+（已配阿里云镜像更佳）
- Python 3.10–3.11（3.12 未验证，faiss/rapidocr 轮子可能缺失）
- MySQL 8.0（本项目附带免安装版于 `D:\medguard-mysql\`，无需系统安装）

### 3.2 MySQL
```bat
rem 首次初始化（数据目录已随包提供则跳过）
D:\medguard-mysql\server\bin\mysqld --initialize-insecure --datadir=D:\medguard-mysql\data
D:\medguard-mysql\server\bin\mysqld --defaults-file=D:\medguard-mysql\my.ini --console
rem 设置root密码为 medguard123，并建库：
mysql -uroot -e "ALTER USER 'root'@'localhost' IDENTIFIED BY 'medguard123'; CREATE DATABASE IF NOT EXISTS medguard DEFAULT CHARSET utf8mb4;"
```
> 注意：MySQL 必须装在**纯英文路径**（如 `D:\medguard-mysql`），否则部分 Windows 环境会因中文路径启动失败。

### 3.3 AI 服务
```bat
cd D:\智慧养老安全用药辅助平台\ai-service
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
.venv\Scripts\python main.py
```
首次启动自动：下载 bge-small-zh-v1.5（HF 镜像）→ 构建 490 片段 FAISS 索引并持久化 → 从后端拉取药品词典与规则（后端未启动时用本地 `data\*.json` 兜底）。

### 3.4 后端
```bat
cd D:\智慧养老安全用药辅助平台\backend
mvn package -DskipTests
java -jar target\medguard-backend.jar
```
配置见 `src\main\resources\application.yml`（数据库地址/账号、AI 服务地址、服务间密钥、JWT 密钥均可用环境变量覆盖）。

### 3.5 前端
H5 与管理后台为纯静态文件，由后端 `WebConfig` 直接映射托管，无需构建。修改后刷新浏览器即可。
静态映射：`/` → `frontend/portal/`（**统一入口页**：单个「进入平台」按钮 + 演示账号表 + 服务状态三灯；登录不同账号进入不同角色页面）；`/h5/**` → `frontend/h5-app/`；`/admin/**` → `frontend/admin-web/`。小程序产物在 `frontend/uniapp-miniprogram/dist/build/mp-weixin`（微信开发者工具直接导入，AppID 选测试号，勾选"不校验合法域名"）。

## 4. 关键环境变量（均可选）

| 变量 | 默认 | 说明 |
|---|---|---|
| `MEDGUARD_SERVICE_KEY` | medguard-internal-2026 | 后端↔AI 服务间签名密钥（两边要一致） |
| `MEDGUARD_BACKEND_URL` | http://127.0.0.1:8080 | AI 服务回源后端的地址 |
| `MEDGUARD_EMBED_MODEL` | BAAI/bge-small-zh-v1.5 | 向量模型 |
| `MEDBOX_YOLO_MODEL` | （空） | **自训药盒检测权重路径**；不配则用 yolov8n(COCO) 演示检测链路并在响应中如实标注 `detect.mode` |
| `MEDGUARD_LLM_API_KEY` / `MEDGUARD_LLM_BASE_URL` / `MEDGUARD_LLM_MODEL` | （空） | 配置后问答走 LLM 受控生成（仍强制引用+拒答），不配走抽取式合成 |
| `MEDGUARD_REFUSE_SCORE` | 0.35 | RAG 拒答阈值（最高余弦低于它则拒答） |
| `MEDGUARD_RETRIEVE_K` | 6 | 混合召回单路 K |

**大模型接入（阿里云百炼，OpenAI 兼容协议）**：推荐把三个 `MEDGUARD_LLM_*` 变量写进 `ai-service/.env`（参照同目录 `ai-service/.env.example` 复制填写），AI 服务启动时自动加载，真实密钥文件已被 `.gitignore` 排除且**不会打进交付 zip**。百炼示例配置：

```ini
# ai-service/.env
MEDGUARD_LLM_API_KEY=sk-你的百炼APIKey
MEDGUARD_LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
MEDGUARD_LLM_MODEL=qwen-plus
```

- 密钥获取：百炼控制台 → API-KEY 管理（免费额度即可支撑答辩演示）。
- 配置后 `/qa` 返回 `mode=llm`（生成内容仍被提示词约束：只准引用检索片段、逐句 [来源N] 标注、越界问题拒答）；未配置自动回退 `mode=extractive` 抽取式合成，功能不中断——**离线答辩同样可演示**。
- 可观测：`GET :8100/health` 的 `llmGeneration` 字段实时反映是否启用。
- 隐私边界：启用 LLM 时发送给云端的是「检索片段 + 问题 + 在用药名称」，不包含手机号/姓名等个人身份信息（后端代理层已脱敏）。

## 7. 常见问题（本项目实际踩过并修复的坑）

| 现象 | 原因 | 解决 |
|---|---|---|
| 后端启动报 `Unsupported character encoding 'utf8mb4'` | JDBC URL 里 `characterEncoding` 只认 Java 字符集名 | URL 用 `characterEncoding=UTF-8`（表字符集仍是 utf8mb4） |
| FAISS `save_local` 报 `could not open ...中文路径... for writing` | faiss C++ `fopen` 不支持非 ASCII 路径 | 已改 `faiss.serialize_index` + `np.save` 自实现持久化（`rag.py`） |
| PowerShell 5.1 发中文 JSON 后端收到 `?????` | `Invoke-RestMethod` 字符串体默认编码非 UTF-8 | 一律用 `[Text.Encoding]::UTF8.GetBytes($json)` 字节体 + `charset=utf-8`；`.ps1` 文件存 UTF-8 with BOM |
| 识别首次调用 8–10 秒 | OCR/模型懒加载 | 属正常，第二次起 1–2 秒；可在启动后先空跑一次预热 |
| 启动瞬间定时任务报 `mg_checkin doesn't exist` | 调度器先于建表任务跑了一次 | 无害，60 秒后自愈；介意可调大 `spring.task.scheduling` 初始延迟 |
| 向量检索分数全 0 | LangChain FAISS 的 `index_to_docstore_id` 值是 UUID 而非行号 | `rag.py::_cache_doc_vectors` 已按 docstore 内容匹配行号 |

## 8. 生产化差距（如实说明）

- JWT 密钥、服务间密钥为演示值，生产必须更换并走密钥管理；
- 药品/规则种子数据为课程项目整理，**上线前须由执业药师逐条复核**（数据内已带 `reviewedBy` 待复核标记与管理端审核流）；
- 药盒检测当前为演示模式（yolov8n COCO 通用检测 + 全图 OCR），生产需自训药盒数据集（标注规范见 `docs\数据集与标注规范.md`）后通过 `MEDBOX_YOLO_MODEL` 挂载；
- 未做 HTTPS/域名/容器化，生产部署建议 Nginx + Docker Compose + 云数据库。
