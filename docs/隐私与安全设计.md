# 隐私与安全设计说明书

> 智慧养老安全用药辅助平台（安心药助手）· MedGuard v1.0
> 对应答辩问题："隐私性你怎么保证的？""弹窗震动是怎么做的？"

---

## 1. 设计原则

| 原则 | 落地方式 |
|---|---|
| 最小收集 | 只收手机号、姓名、出生年份、用药计划；不采集身份证号、位置、通讯录 |
| 知情同意 | 注册时勾选协议；健康信息**单独同意**（`mg_user.health_consent_at`），可在「我的」页随时撤回，撤回不影响基本功能 |
| 默认脱敏 | 家属端看到的老人手机号默认打码（`139****1111`），后端统一脱敏后下发，前端无明文可拿 |
| 可撤回、可删除 | 授权随时撤销即时生效；注销账号后数据 30 天级联彻底删除 |
| 全程留痕 | 敏感操作写审计日志（`mg_audit_log`，保存 6 个月） |

## 2. 分域安全措施

### 2.1 传输与认证
- **JWT 无状态令牌**：登录后签发，后端 `AuthInterceptor` 对 `/api/**` 统一拦截（登录/注册/健康检查/内部接口除外）；令牌过期或伪造返回 401。
- **角色三级隔离**：ELDER / FAMILY / ADMIN 三角色，接口级校验——老人访问管理端接口直接 403（e2e 用例验证）；家属只能访问**已授权老人**的数据（每次请求校验 `mg_family_bind` 状态为 APPROVED）。
- **服务间通信**：后端 ↔ AI 服务走内网 127.0.0.1，附 `X-Service-Key` 签名头，密钥可用环境变量覆盖，缺省值仅用于本地演示。

### 2.2 存储
- **密码不存明文**：BCrypt 加盐哈希（强度 10），数据库泄露也无法反推密码。
- **软删除 + 定时清除**：注销只置 `deleted=1`、`deleted_at=now()`（留 30 天后悔期），到期级联物理删除本人全部数据。
- **数据本地化**：演示版全部数据落在本机 MySQL，不出境、不上公有云。

### 2.3 药品照片——即传即删
这是老人端最敏感的输入。处理链路：

```
手机拍照 → 前端压缩(canvas≤1280px) → multipart上传
→ AI服务内存中解码字节 → YOLO检测+OCR识别 → 返回文字结果
→ 立即释放图片字节（不落盘、不缓存、不进数据库）
```

- AI 服务 `main.py` 识别完成后显式清空图片缓冲（`data = b""`），**磁盘上不存在任何用户照片**；
- 数据库 `mg_recognize_log` 只存识别出的**文字**（药名、置信度、是否确认），无图片字段；
- 答辩口径：「照片即传即删，平台不保存原图」——可用文件系统和数据库双重验证。

### 2.4 家属授权矩阵（细粒度 scope）
家属不是"绑定就能看全部"，而是按老人逐项勾选的范围授权：

| Scope | 含义 | 未授权时的表现 |
|---|---|---|
| VIEW_SUMMARY | 看今日服药概况 | 概况接口 403 |
| VIEW_ADHERENCE | 看依从率与历史记录 | 记录接口 403 |
| RECEIVE_ALERTS | 实时接收风险警报（SSE） | 不进推送名单 |
| MANAGE_PLANS | 代办用药计划（增/停） | 代办接口 403 |

- 授权存 `mg_family_bind.scopes`（CSV），**老人可随时撤销**（`revoked_at` 即时生效，家属下一次请求即 403）；
- 家属侧看到的老人信息统一脱敏；
- 绑定需老人**同意**（PENDING → APPROVED 流程），杜绝单方面偷看。

### 2.5 审计日志
登录、授权变更、计划增删、打卡、识别、问答全部写 `mg_audit_log`（谁、何时、何 IP、对什么对象、做了什么），保存 6 个月。管理后台可查，形成"操作可追溯"闭环。

### 2.6 AI 问答的隐私边界
- 发给云端大模型（百炼 qwen-plus）的内容仅为：**检索到的知识片段 + 用户问题 + 在用药名称**；
- **不含**手机号、姓名、住址等身份信息（请求体结构上就没有这些字段）；
- 大模型密钥存 `ai-service/.env`（已 gitignore、不进交付包），仓库与 zip 中只有 `.env.example` 模板；
- 不配密钥时自动回退本地抽取式回答，**数据完全不出机器**——离线答辩模式零外发。

### 2.7 SSE 令牌的工程取舍（如实说明）
浏览器 `EventSource` 不支持自定义 Header，家属实时警报流采用 `?token=JWT` 查询参数传递。风险与对策：URL 可能进访问日志 → 本服务为内网演示、Nginx 类网关未启用；生产化方案是改用 WebSocket 子协议传 token 或一次性 ticket。答辩被问到就按此如实回答，体现权衡意识。

## 3. 弹窗震动是怎么做的

### 3.1 H5 端（老人/家属）：`navigator.vibrate` 模式震动
`core.js` 统一封装 `buzz(pattern)`，按**事件语义**分级触发：

| 事件 | 震动模式（毫秒） | 体感 |
|---|---|---|
| 高危用药冲突（保存计划/进首页/今日页） | `[350,150,350]` | 长-停-长，"必须停下来看" |
| 中低危冲突提示 | `[180,100,180]` | 双段，"注意一下" |
| 到点未服药提醒 | `[250,120,250]` | 双段偏长，"该吃药了" |
| 问答被拒答（超出用药范围） | `[140,80,140]` | 轻双段，"此题不答" |
| 打卡成功 / 安全保存 | `60` | 轻一下，正反馈 |
| 报错 toast | `[260,100,260]` | 随错误弹窗 |

配套机制：
- **「我的」页震动总开关**（`mg_buzz` localStorage），关闭后 `buzz()` 静默跳过；
- iOS Safari **不支持** `navigator.vibrate`（苹果 WebKit 限制）——自动降级为弹窗 + TTS 语音播报，文案里如实标注；Android Chrome / 微信内置浏览器均支持；
- 弹窗（toast）本身按级别配色 + 自动朗读（TTS 开时），"视觉+听觉+触觉"三通道确保老人感知到。

### 3.2 小程序端（uniapp）
`utils/tts.ts` 的 `feedback(kind)` 三档：
- `ok` → `uni.vibrateShort`（单次短震）
- `warn` → `vibrateShort` × 2（间隔 220ms）
- `err` → `uni.vibrateLong`（长震）
微信/支付宝小程序容器原生支持，iOS 也有效（与 H5 的差异点，答辩可作为"多端适配"案例）。

## 4. 数据库层的隐私字段设计

见《数据字典》。与隐私直接相关的字段：
- `mg_user.consent_at / health_consent_at`：两级知情同意时间戳；
- `mg_user.deleted / deleted_at`：软删除 + 30 天清除窗口；
- `mg_family_bind.scopes / status / revoked_at`：授权矩阵全生命周期；
- `mg_recognize_log`：无图片列（设计上杜绝存图）；
- `mg_audit_log.ip / created_at`：追溯依据。
